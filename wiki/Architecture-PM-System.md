# Architecture: PM system

This page describes what holds the pm group's work together across sessions and initiatives, the way [Architecture: SDLC system](Architecture-SDLC-System) describes the SPEC-TS ledger for the developer group.

Where the developer group grounds every decision in one ledger, the pm group grounds it in a **constitution** hierarchy: an overall practice constitution at the repository root, and a per-initiative constitution that inherits it and records only its overrides. Every pm skill reads the applicable chain, most-specific last, before it drafts anything — the seven sections (principles, value propositions, positioning, CX philosophy, building approach, prioritization framework, research bets) and the at-least-quarterly review cadence are in [CONSTITUTION.md](https://github.com/tqnonline/skills/blob/main/skills/pm/constitution/CONSTITUTION.md).

Every real-work pm skill also runs the same self-maturing cycle: **DDDD** — Discover, Define, Design, Deliver — orthogonal to the four human gates. The gates decide when a human signs off; DDDD is how a skill does its own work in the stretch between one gate and the next, threaded into `discover`, `map`, `tom-architect`, `carve`, `prd-draft`, `case`, `roadmap`, `realize`, and `report`. The full doctrine, including how it relates to Framing/Investment/Quality/Commitment, is in [DDDD.md](https://github.com/tqnonline/skills/blob/main/skills/pm/DDDD.md).

The substrate all of this is written against is an **initiative repository** — one per initiative by default, a monorepo of `initiatives/<slug>/` folders with Git LFS for binary artifacts, or the software repository's own `specs/` tree when the initiative delivers code, so the pm group never stands up a parallel system of record next to the developer group's. `discover` verifies or bootstraps this substrate at intake. The three modes are in [INITIATIVE-REPO.md](https://github.com/tqnonline/skills/blob/main/skills/pm/INITIATIVE-REPO.md).

Two more doctrines complete the system: [AGENT-OWNERSHIP.md](https://github.com/tqnonline/skills/blob/main/skills/pm/AGENT-OWNERSHIP.md) is the pre-gate blind-spot checklist every gate runs before a human decides, and [RESEARCH-AGENTS.md](https://github.com/tqnonline/skills/blob/main/skills/pm/RESEARCH-AGENTS.md) governs how raw inputs, commissioned research, and provoked hypotheses become the citation corpus `grill`'s with-docs mode draws from. See [Architecture: PM journey](Architecture-PM-Journey) for how these pieces fit into the end-to-end path, and [Architecture: PM arrange](Architecture-PM-Arrange) for how a skill chooses its own execution shape within it.
