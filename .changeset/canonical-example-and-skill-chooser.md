The documentation site now runs on one canonical enterprise example instead of a different invented scenario on every page. A new reference page, `/example/`, introduces QuenServe, a field-inspection product, and lays out one epic with three features and six user stories that every skill's worked example traces back to. Each of the 34 skill pages carries a scenario rebased onto that same product, pitched at the altitude the skill actually works: a product-discovery skill names the product without an id yet assigned, a delivery skill names the specific story it ships, and a governance or leadership skill names the epic it oversees. A test suite parses the reference page for its own id list and product name, then checks every page on the site against it in both directions: an id used anywhere that the reference page does not define fails by name, and an id the reference page defines but no other page uses fails the same way.

Each skill page's "When to reach for it" section is restructured. Five separate per-tool blocks, one prompt-card apiece, are replaced by one shared install line stated once and three tool-mechanism groups — Claude Code, OpenCode, and a merged "Catalog readers" group for Cursor, Codex, and GitHub Copilot, grouped because those three read the same catalog the same way. The Tools page and the install reference in `.agents/install-block.md` are restructured to match, explaining what each install command does and how a team installs one group or one skill instead of the full catalog. The coverage test that enforces the page contract now accepts only this group shape; the retired five-block shape fails the build.

The home page and the pipeline guide (`/how-it-fits/`) both carry a new skill chooser: a three-question decision tree — what are you doing, at what altitude, and what is the moment — that narrows down to one skill and links its page. The tree is generated, not hand-typed: every leaf is traced back to a real routing map inside `ask-fde` and `ask-pm`, and the altitude and moment questions are grounded in the same vocabulary `conduct` and `arrange` use in their own rubrics, so the chooser drifts from neither router if either one changes. A `--check` mode catches that drift before it ships.

All of it is enforced by tests: the rebuilt tool-coverage contract, the scenario-and-id consistency check against the reference page, and the chooser generator's own drift check, together with a manual browser drive that clicks through a real chooser path, copies a prompt card, and toggles the theme against an assembled render of the real site templates.
