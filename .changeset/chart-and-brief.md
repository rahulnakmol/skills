Two new skills address work that outgrows a single agent session. The pm group gains a seventeenth skill, `chart`: an initiative too large or too uncertain for `discover` → `map` → `carve` to run in one pass is charted as decision tickets on the team's tracker, each ticket asking one question sized to one session and carrying one of four types — evidence, option, alignment, or enablement — that decides who resolves it and whether it can run in parallel. The chart is an index rather than a store, so a decision lives in exactly one place; four ticket states (ready, blocked, claimed, closed) make the takeable edge of the plan readable without opening anything; a claim protocol lets several agent sessions work one chart concurrently; and what cannot be settled leaves as a `raid` entry rather than sitting open forever. `report` now sources Progress and Priorities from a chart where one exists, so a large effort produces status without anyone writing a status update, and `ask-pm` routes "this is too big to plan in one go" to it.

The productivity group ships its first skill, `brief`: the rules, definitions, and boundaries a team's agents read, broken into three layers — always-loaded rules, a shared glossary, and on-demand references — and placed in the file each surface actually loads. `SURFACES.md` maps Claude Code, Claude Desktop, Cowork, OpenCode, Codex, Cursor, and Copilot to their rule files, names one canonical file with pointers elsewhere, and covers the two surfaces that have no repository file at all. `RULES.md` covers the anatomy of a rule that fires, why a prohibition underperforms the positive instruction beside it, when the environment should stay the source of truth, and why a rule is tested by running work rather than by rereading the file.
