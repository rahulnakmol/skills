Ship a Codex stop hook for grit, so completion enforcement is no longer Claude Code only. Codex reads lifecycle hooks from a `hooks.json` file, and its `Stop` event fires when a session is about to finish. A new launcher at `adapters/codex/hooks/stop-hook.mjs` binds to that event and keeps a session from ending while the gate ledger still has unmet gates. The contract was read from the `openai/codex` repository rather than inferred: the generated schema `codex-rs/hooks/schema/generated/stop.command.output.schema.json` and the handler `codex-rs/hooks/src/events/stop.rs`. It turns out to be wire-compatible with the Claude Code contract, so both adapters delegate to the single vendored implementation at `skills/core/grit/scripts/stop-hook.mjs` and the two tools enforce one ledger parser rather than two that can drift. The installer gains a `--tool codex-hooks` target, opt-in and excluded from the default install for the reason ADR 0006 gives.

Fix the `--tool claude-hooks` installer, which registered a hook that never ran. It copied the launcher to a user-level path but then registered the project-relative command `node .claude/hooks/grit-stop-hook.mjs`, so unless the project directory happened to be the home directory, the recorded path pointed at a file that was never written. The arm now registers with `--user`, and `install-hooks.mjs` names the launcher by absolute path when it writes a user settings file, because such a file applies to every project and a relative path would resolve somewhere different in each one. Project and `--local` targets keep the relative path, which keeps a settings file that is normally committed free of one machine's absolute paths. An entry left behind by the earlier behaviour is repaired in place rather than left pointing at nothing.

Make `scripts/link-skills.sh` run on macOS. It used `mapfile`, a bash 4 builtin, and macOS ships bash 3.2, so the script exited 127 partway through and the harness could not go green there.
