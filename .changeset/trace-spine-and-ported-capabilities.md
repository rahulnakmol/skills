The repository gains a trace spine and a contract harness, and sixteen capabilities ported from the reference set arrive as drafts bound to both.

`skills/core/TRACE.md` defines the run trace: the record a skill writes while it works, holding what it was given, what it decided, what evidence it saw, and what it left open. A trace lives beside the gate ledger it accompanies, at `.grit/<scope>/TRACE.md`, rather than in a second state directory, because a repository carrying two partial records of the same run has gained disagreement rather than an audit trail. The document also defines the four-key contract block every new skill carries — its invocation axis, the limb of the repository's promotion test it satisfies, the tool verbs it may use, and the kind of entry it appends — and the replay protocol a later session follows to resume work it did not start.

Two harness files enforce that contract. `test/structure/frontier-contracts.test.mjs` checks that every draft declares a thesis limb from a closed set, draws its verbs from a closed set and names a human approval step whenever it declares the outward-facing `publish` verb, agrees with its own title on the invocation axis, holds a basename unique against every promoted skill, respects group independence, points at every doctrine sibling it ships, and stays out of the README and the plugin manifest until it is promoted. `test/structure/house-voice.test.mjs` enforces the rule `.agents/writing-docs.md` states — no marketing vocabulary, no first-person cheerleading, no exclamation points or decorative emoji, American spelling, and a description substantial enough for a model to route on. Words with a legitimate technical sense here stay off the banned list, because a check that forces correct prose to be mangled teaches authors to work around the harness rather than to write well.

Ten of the sixteen ported capabilities ship promoted. In the developer group: `tdd` drives one vertical slice from a failing test to passing code; `debug` runs a gated diagnosis loop that reproduces before it theorizes and tests one falsifiable hypothesis at a time; `prototype` answers a single design question with code it then deletes or deliberately graduates; `refactor` surveys a codebase for deepening opportunities and stops for a person to choose which one is worth working; `glossary` builds the project's shared language, recording each term with an explicit list of the near-synonyms it replaces; `triage` moves incoming issues through one role at a time using the repository's own label vocabulary rather than an invented one; and `wizard` generates a resumable script for the steps only a human can perform, refusing to generate one where the agent could do the work itself.

The core group gains two. `research` investigates against primary sources and writes cited findings into the repository, so the reading is done once rather than repeated each session, and it labels a claim it could not source rather than asserting it quietly. `retro` closes the harness loop: it reads accumulated traces, treats a single failure as an anecdote and a pattern across three or more runs as a finding, separates a defect in the instructions from a defect in following them, and proposes changes as a pull request a person approves. It never merges its own improvements, because a system that both writes and accepts its own rules has no gate left.

The productivity group gains `handoff`, which projects a run's trace into a document the next session picks up cold. It is assembled from what was recorded while the work happened rather than remembered at the end, and it carries what was tried and abandoned, which is the part a summary drops and the next session would otherwise retry.

Each promoted skill carries a documentation page, a wiki stub, a routing case in the selection eval, and an entry in the `ask-fde` router. The remaining six stay under `drafts/`, where they are inert: the installer, the plugin manifest, the documentation site, and the skill chooser all read `skills/`, so a draft ships nothing until a person promotes it. They are `questionnaire`, `wait-what`, and `teach` in productivity, and `freewrite`, `outline`, and `draft`, which will open the writing group. The contract checks follow a skill across that boundary rather than stopping at it, so a promoted skill is held to the declaration it made as a draft. `retro` closes the harness loop by mining accumulated traces for failure patterns that repeat across three or more runs and proposing skill changes as a pull request a person approves, because a system that both writes and accepts its own rules has no gate left.

The `deliver` skill gains two doctrine documents rather than two new skills, since their host already exists and nobody invokes them by name. `MERGE.md` resolves an in-progress merge or rebase by the intent behind each side, treats the full merged suite as the evidence a successful compile is not, regenerates lockfiles with the project's own tooling, and routes a genuine design conflict to a person. `REPO-SETUP.md` gains commit-time guardrails: pre-commit hooks that run only what is fast, because a hook that runs the full suite is disabled within a week and leaves no commit-time check at all, and destructive git commands blocked at the point of execution, each block naming the safe alternative so the guardrail is not simply switched off.
